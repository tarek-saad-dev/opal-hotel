# Opal Legacy — Media-First Dynamic CMS V2

## Goal
Actual hotel photography and film are the center of the website design. Every important visual shown in the current UI can be selected from the **owner's approved media library**, without another code deployment. V1 remains operational for backwards compatibility.

## Owner interface

Open `/admin` → **مكتبة الوسائط V2**.

1. **Bulk upload**: Select multiple JPG/PNG/WebP images and/or MP4 files. Browser images are resized to a maximum of 2200px and re-encoded as WebP (or JPEG fallback) before upload, removing typical image metadata and reducing loading time. The image upload endpoint caps each result at **4 MB**. Individual MP4 files must be **50 MB or smaller**; browser uploads do not transcode video.
2. **Catalog (optional)**: Uploaded photos are ready to choose immediately. If helpful, give them names, categories and Arabic/English descriptions. The frontend automatically supplies safe localized alt text when no description is entered. No per-photo checklist is required.
3. **Map to layout**: Choose up to six still images for the fallback Hero slider, an Overview **large image** and **small inset**, images for the Facilities and Location sections, a customizable mixed image/video Gallery (up to 100 assets), and separate cover, gallery (up to 16 images) and optional film for each room concept.
4. **Arrange**: Use arrow buttons or desktop drag-and-drop to reorder Hero and Gallery media. Room galleries have up/down controls for mobile accessibility.
5. **Save & Publish (default)**: After choosing thumbnails, click **حفظ ونشر الآن** once. Confirm that you have rights to use the selected photos/videos **as one batch**, and the owner UI saves and publishes them. *Uploading alone never changes the live website*. For editors who need staging, **حفظ المسودة** and authenticated `/ar/preview` / `/en/preview` remain available; previews show pending selections privately.

There is also a separate **Hero Video V1** editor for the short autoplay poster-first Hero, and **legacy six-photo slots** in the old media editor. The new V2 placements take precedence over legacy photos **per placement** when the selected asset is approved; otherwise the prior safe/demo visual remains. To restore an old image simply clear its V2 assignment and publish.

## Actual frontend mapping
- `PremiumMasthead`: published V2 Hero image sequence; Hero Video V1 continues to override the still-slider only when explicitly enabled and approved.
- `PremiumStory`: owner-selected large and small photo, including the former hardcoded image pair.
- `PremiumFacilities` and `PremiumLocation`: optional real photography panels.
- `PremiumRooms`, `/rooms`, room cards, room detail galleries, room lightboxes, and booking preview: per-concept cover/gallery picks. Room detail videos are click-to-play and `preload="none"`.
- `PremiumGallery`: selected image collection, localized alt, category filters, independent, click-to-play films with optional approved posters.
- Logo and headings remain shared across AR/EN, while the site text stays localized.

## Security and persistence
- File bytes are stored outside Git and outside the static web root in `/var/lib/opal-hotel-cms/media` and `/var/lib/opal-hotel-cms/videos`. CMS metadata, draft, published revision and history stay under the existing private CMS directory.
- Old published JSON lacking `media.visual` continues to load with a default empty library. No destructive database migration or reset.
- Asset paths are generated by the CMS upload endpoints, not arbitrary owner-supplied URLs. The server validates types, category, maximum counts, reference integrity, duplicate placements and known room concept slugs.
- Anonymous visitor access is limited to assets **explicitly covered by the owner's batch-rights confirmation and assigned in a published snapshot**. Unapproved, unassigned or draft-only files return 404 even when the filename is guessed. A published video's poster is public only when its photo asset is also approved.
- Videos are served with HTTP byte-range support (206) to avoid forcing complete movie downloads; no guest media editing actions are enabled.
- Deleting a library *reference* does not erase historical file bytes or invalidate older published media snapshots. A separate retention-aware garbage collector is a future task, not part of V2.
- Permission to publish is held by the existing authenticated single owner; there are no public upload endpoints.
- New library is capped at 160 assets / 100 Gallery assignments per version to bound the single-VPS CMS. Large scale requires object storage and a CDN.

## Performance / media quality
- Hero LCP image must be selected, compressed and verified. Image raster dimensions are capped to 2200px on supported browsers before uploading.
- Use the short muted Hero Video as a separate optional experience with a Poster and mobile variant. Do not use the full 4-minute hotel film as a background.
- Gallery and room films have `controls`, `playsInline` and `preload="none"`; they do not auto-download on initial page load.
- For a high traffic production website, put the approved media behind object storage + CDN; the present private VPS is a deliberately simple starting point.
- Confirm media licensing and real hotel identity once during publication. Do not rename renderings or illustrative stock as authentic hotel photos. The batch publish endpoint approves only selected media (plus any linked video poster) and leaves unused uploads private.

## Deployment and verification
Run repository checks: `npm test && npm run typecheck && npm run build`. The browser CMS integration runs against **isolated local test data**, not live owner content, and checks unpublished access denial, publishing approved image/video, Arabic and English story, Hero, gallery, rooms and range streaming.

After the PR passes CI and merges, deploy the Opal service on the VPS as described in `docs/CMS_SETUP.md`. Then use the owner UI to upload actual photos (ideally original camera files, not WhatsApp-compressed), choose placement thumbnails and click «حفظ ونشر الآن» with a single rights confirmation. No manual bilingual descriptions are required. No further SSH actions are needed for ordinary content changes.

**Operational requirement:** Arrange encrypted off-VPS backups of the private CMS directory including metadata, photos, videos and history, and verify a restore into a safe test directory. V2 does not implement automatic backup or an external CDN.

**Not included:** real booking/availability/payment systems, publication of unverified hotel claims, image/video editing suites, AI-generated property media, or automatic creation of hotel image assets.
